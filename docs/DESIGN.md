# GoldBench 设计概要

版本：v1.0；本地应用：v0.1.0。本文供项目协作与代码阅读使用，不包含账号权益、密钥、原始新闻或完整私人讨论记录。

## 目标与实验分组

在统一账户、信息截止、工具权限和预算下，比较LLM自主获取信息、判断及交易决策的能力。XAU/USD是唯一可交易标的，其他市场数据仅作为研究信息。

默认参赛配置为GPT-5-mini、Gemini-3-Flash、Claude-Haiku-4.5、GPT-5-nano，各运行基础组/工具扩展组，每组独立重复2次，共16条轨迹。名称是设计配置，实际供应商版本与能力须在实验前验证冻结。

基础组只获得必要状态和提交工具；扩展组额外获得研究工具及最近5轮结构化历史。因此分组差异同时包含工具与记忆，不能把收益差单独归因为工具。

## 日历、信息截止与价格

- 北京时间周一至周五每日一轮，事先确定的全天休市日跳过；不由事后行情是否存在来改日历。
- D日06:45冻结信息，06:53停止新研究，06:55截止提交，07:00为名义执行时刻。
- 使用同名源日期的Tushare日线 `bid_open/ask_open` 作为模拟成交代理，不声称是真实07:00可成交价格。
- 周末原始行保留，但不生成轮次、不作为预测端点、不加入SMA20。低tick仅作提示，不能用整日最终tick数量事后决定开盘交易。
- 日期d完整日线按d+1日00:00 UTC解锁；可靠实际可得时间更晚时取更晚。执行bar未来的high/low/close/tick不可提前给模型。
- 预测绑定本轮至下一预定轮次的开盘中间价收益。端点缺价记NA，不悄悄跨到下一个有价日。

源日期约定只是显式实验协议，覆盖与经济时间仍须核验，不能以设计确定代替数据合格。

## 账户与订单

- 每个账户初始10,000美元，单一有符号黄金净持仓，单位金衡盎司。
- 默认允许做空、最多1倍敞口、可满仓；开启买卖点差，滑点/佣金/融资费默认关闭。
- 清算净值：多头按bid、空头按ask。目标权重为调仓后中间价名义金额除以扣费后的清算净值，执行引擎解数量与费用的关系。
- 数量向零舍入至0.0001盎司，重新校验敞口；使用Decimal避免每天美分舍入。
- `hold`保持数量；`rebalance`调整比例，相同权重也可能产生再平衡交易。
- 单笔现金分录更新后统一计算净值，不额外重复叠加已实现损益。点差已包含在报价中，不另扣一次。
- 净值非正时终止账户并按统一规则退出，保留真实负余额。实验统一在最后预测终点退出；缺终点报价标不完整，不用旧价发布最终排名。

## 提交与预算

每日提交 `action`、`target_weight`、`expected_return`、`prob_up`、`rationale`、`evidence_ids`。收益为小数，概率为0—1；hold权重必须为null。

首次合法提交锁定；最多2次非法提交纠正，必须在原预算内完成。最终无合法提交则保持数量，预测缺失不填0或0.5。

历史经济预设每轮20k累计输入、2k输出、研究调用次数不限、10分钟；提交预留4k输入/600输出，包含于总额。前瞻原预设100k/16k、30调用，前瞻日数口径与独立费用尚待冻结。

月历史模型预算10美元包括裁判、试跑和重试。发请求前原子预留在途费用，未知完成状态不自动再次生成。

## 工具、数据与记忆

研究工具目录：get_prices、get_macro、get_positioning、search_news、read_news、run_python、get_history、read_webpage、run_backtest。模型只接白名单工具，不直接持有供应商密钥。

- 黄金日线截止过滤并生成授权数据句柄。
- 新闻按需取回时间片、触限分窗、去重缓存，搜索和正文读取使用同版本。保存实际证据，避免供应商更新导致不可复核。
- 宏观按发布时间而不是统计期开放，经济日历今值在发布后解锁；历史内容/数值采用显式供应商可信假设。
- Python与回测只能使用已获得数据；Python需要隔离执行，禁止宿主凭证、文件和任意网络访问。
- 各实验、模型、组别和重复隔离；自动历史仅5轮，主动读取限最近30轮；未成熟标签及裁判反馈不进入交易Agent。

首版已实现的适配范围与仍待准备的数据详见README和LOCAL_DEVELOPMENT.md。

## 评测与裁判

交易以扣费净收益为主，同时报告回撤、敞口、换手与基准差；预测报告MAE、Brier、样本数及共同有效日期结果。模型API费用单独报告，不混入交易收益。不合成四维万能总分。

三个确定性基准为零息现金、首次成功建仓后保持数量的黄金买入持有、使用连续20个完整可见bar的SMA20。各基准共享账户、费用、日历和异常规则。

双裁判为GPT-4.1-mini与Gemini-3.1-Flash-Lite，隐藏模型身份、未来结果和另一裁判的分数。三个维度分别0—4：信息理解、分析与行动一致性、证据支持。平台证据丢失记NA，不补0或缩放缺失维度。

任一维分差至少2分、NA或关键引用争议进入人工复核；另按模型×组分层抽查至少20%，覆盖两次重复。人工先盲评，后核对裁判理由，最终裁决替代机器均值并保留历史版本。

## 架构与交付

数据适配/缓存 → 截止快照 → Agent循环 → 锁定决策 → 确定性账本 → 指标与裁判 → FastAPI → React界面。

SQLite保存任务、账户、配置、预算、证据索引与裁决。独立worker在历史同日全部轨迹落定后推进下一日，默认并发2。界面包含总览、比较、回放、复核、运行状态；数据缺失显示断点，失败hold与主动hold分开。

正式实验前必须通过数据覆盖、模型兼容、实际计费、隔离执行、时间边界与故障恢复验收。工程测试闭环不等于正式研究结果。
